# Spec Delta

## Purpose

Позволяет локально извлекать реквизиты российского свидетельства о рождении из выбранного файла и передавать их в отдельные поля общей формы без смешения с паспортными данными.

## ADDED Requirements

### Requirement: Выбор и локальная обработка свидетельства о рождении

Система SHALL предоставлять явный тип «Свидетельство о рождении» и SHALL распознавать для него один выбранный локальный файл `.jpg`, `.jpeg`, `.png` или `.pdf` без обращения к сетевому сервису. Система MUST сохранять абсолютный путь и файловый доступ вне Angular renderer.

#### Scenario: Распознавание изображения

- **WHEN** пользователь выбирает тип свидетельства о рождении и запускает распознавание читаемого JPG, JPEG или PNG
- **THEN** система использует правила свидетельства о рождении и возвращает структурированный результат для общей формы

#### Scenario: Распознавание PDF

- **WHEN** пользователь выбирает тип свидетельства о рождении и запускает распознавание читаемого PDF
- **THEN** система извлекает реквизиты из относящихся к свидетельству страниц без удалённой загрузки файла

### Requirement: Поля свидетельства о рождении

Система SHALL возвращать отдельно фамилию, имя и отчество ребёнка, его дату и место рождения; фамилию, имя, отчество, дату рождения, гражданство и национальность отца и матери по отдельности; дату государственной регистрации, номер актовой записи, наименование органа ЗАГС, дату выдачи, серию и номер свидетельства. Гражданство и национальность MUST оставаться разными полями.

#### Scenario: Все реквизиты читаемы

- **WHEN** на свидетельстве однозначно читаются перечисленные реквизиты
- **THEN** каждое значение возвращается в своём поле, а сведения отца, матери и ребёнка не смешиваются

#### Scenario: Неуказанная национальность родителя

- **WHEN** национальность родителя в свидетельстве не указана
- **THEN** соответствующее поле остаётся пустым и не заполняется его гражданством

#### Scenario: Реквизит неразборчив

- **WHEN** OCR не может надёжно связать значение с конкретным лицом или названием реквизита
- **THEN** соответствующее поле остаётся пустым, без подстановки соседнего значения

### Requirement: Проверка дат и актовой записи

Система SHALL возвращать календарно корректные даты в формате `YYYY-MM-DD` и сохранять серию и номер документа отдельно от номера актовой записи.

#### Scenario: Дата OCR недействительна

- **WHEN** распознанная последовательность не образует календарно корректную дату
- **THEN** соответствующее поле даты остаётся пустым

### Requirement: Контролируемая ошибка распознавания

Система SHALL завершать распознавание повреждённого, нечитаемого или неподходящего файла контролируемой ошибкой, не раскрывая локальный путь в UI и не изменяя уже введённые поля.

#### Scenario: Выбран другой документ

- **WHEN** пользователь запускает распознавание файла без достаточных признаков свидетельства о рождении
- **THEN** UI сообщает о неуспехе, сохраняя значения общей формы
