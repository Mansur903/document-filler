# Spec Delta

## MODIFIED Requirements

### Requirement: Единая панель данных пользователя

Система SHALL постоянно предоставлять в правой панели доступ к полям российского заграничного и внутреннего паспортов, UAE Residence Permit, свидетельств о рождении и заключении брака, а также к ручным полям `email`, `address`, `phone` независимо от того, какие документы уже распознаны. Панель SHALL использовать компактное расположение полей и собственную вертикальную прокрутку при нехватке высоты, не скрывая доступ к выбору и распознаванию документа. Поля каждого свидетельства SHALL находиться в собственном раскрываемом блоке.

#### Scenario: Форма открыта до первого распознавания

- **WHEN** пользователь открывает приложение для нового пользователя
- **THEN** все поддерживаемые поля пусты и доступны в правой панели, включая `email`, `address` и `phone`; блоки свидетельств находятся в свёрнутом виде

#### Scenario: Поля не помещаются по высоте

- **WHEN** высота окна недостаточна для одновременного отображения всех полей
- **THEN** пользователь может прокрутить правую панель и получить доступ к каждому полю без прокрутки или исчезновения панели выбора документа

#### Scenario: Значение отредактировано вручную

- **WHEN** пользователь изменяет любое поле общей формы
- **THEN** отредактированное значение немедленно становится текущим значением для дальнейшего слияния и генерации документа

### Requirement: Неперезаписывающее объединение результатов OCR

После успешного распознавания система SHALL заполнять только поля, текущее значение которых является пустой строкой, значением OCR, которое само не является пустым. Система MUST сохранять любое уже непустое значение независимо от того, получено оно предыдущим OCR или введено вручную, и MUST поддерживать распознавание всех поддерживаемых типов документов в любом порядке.

#### Scenario: Сначала распознан паспорт

- **WHEN** пользователь сначала распознаёт паспорт, а затем UAE Residence Permit
- **THEN** поля разрешения заполняются без очистки паспортных и ручных полей

#### Scenario: Сначала распознан UAE Residence Permit

- **WHEN** пользователь сначала распознаёт UAE Residence Permit, а затем паспорт
- **THEN** паспортные поля заполняются без очистки полей разрешения и ручных полей

#### Scenario: Новое значение пересекается с заполненным

- **WHEN** новое распознавание возвращает непустое значение для любого уже непустого общего поля
- **THEN** система сохраняет текущее значение поля и игнорирует новое значение OCR для этого поля

#### Scenario: Новое значение заполняет пустое поле

- **WHEN** новое распознавание возвращает непустое значение для пустого поля
- **THEN** система записывает распознанное значение в это поле

#### Scenario: OCR вернул пустое значение

- **WHEN** новое распознавание возвращает пустое значение для любого поля
- **THEN** текущее значение этого поля не изменяется

#### Scenario: Пользователь вручную очистил поле

- **WHEN** пользователь удалил значение поля и последующее распознавание вернуло для него непустое значение
- **THEN** система считает поле пустым и заполняет его новым распознанным значением

#### Scenario: Выбран или заменён файл

- **WHEN** пользователь выбирает другой файл или отменяет диалог выбора
- **THEN** значения общей формы остаются без изменений

#### Scenario: Свидетельства распознаны в любом порядке

- **WHEN** пользователь распознаёт свидетельство о рождении и свидетельство о браке в любом порядке
- **THEN** данные обоих документов сохраняются в отдельных полях и ранее заполненные значения не затираются

### Requirement: Генерация DOCX из общей формы

Система SHALL передавать в выбранный DOCX-шаблон все существующие паспортные поля и поля `residencepermitID`, `visaID`, `visaValidUntil`, `currentOccupation`, `employer`, `email`, `address`, `phone`, а также все именованные поля свидетельств о рождении и браке, используя текущие отредактированные значения общей формы. Для дат SHALL применяться существующее форматирование даты DOCX.

#### Scenario: Шаблон содержит новые плейсхолдеры

- **WHEN** пользователь генерирует документ из шаблона с плейсхолдерами свидетельств
- **THEN** каждый плейсхолдер заменяется текущим значением одноимённого поля общей формы без смешения лиц или типов документов

#### Scenario: Поле осталось пустым

- **WHEN** плейсхолдер присутствует в шаблоне, но соответствующее поле общей формы пусто
- **THEN** генератор обрабатывает его по единому действующему правилу для пустых значений и не использует данные из предыдущего пользователя

## ADDED Requirements

### Requirement: Раскрываемые блоки свидетельств

Система SHALL показывать два независимых блока свидетельств в области ввода, с понятными заголовками, кратким состоянием заполнения и внутренними группами по участникам и реквизитам. Раскрытие и сворачивание SHALL быть доступно клавиатурой и MUST NOT изменять значения формы. После успешного распознавания одного свидетельства система SHALL раскрыть его блок без принудительного сворачивания другого.

#### Scenario: Открытие блока с клавиатуры

- **WHEN** пользователь фокусирует заголовок блока и активирует его клавиатурой
- **THEN** поля блока становятся видимы и доступны для редактирования, а состояние раскрытия объявлено вспомогательным технологиям

#### Scenario: Блок свёрнут после ручного ввода

- **WHEN** пользователь ввёл данные свидетельства и свернул его блок
- **THEN** краткое состояние показывает наличие данных, а значения сохраняются для DOCX и последующего раскрытия

#### Scenario: Успешно распознано свидетельство

- **WHEN** завершается распознавание свидетельства о браке или рождении
- **THEN** раскрывается соответствующий блок, чтобы пользователь мог проверить результат

#### Scenario: Новый пользователь

- **WHEN** пользователь подтверждает сброс заполненной формы
- **THEN** поля обоих свидетельств очищаются вместе с остальной общей формой
