# Proposal

## Why

Текущий паспортный OCR возвращает страну выдачи и дату выдачи, но не извлекает текст органа, выдавшего паспорт. Из-за этого пользователю приходится переносить значение вручную, а шаблоны DOCX не могут использовать отдельный реквизит `authority`.

## What Changes

- Добавить в результат распознавания российского заграничного паспорта строковое поле `authority`, извлекаемое из визуальной подписи `Authority` и связанного с ней значения.
- Возвращать `null`, если подпись или значение органа выдачи отсутствует либо не может быть определено однозначно, не подставляя соседние реквизиты.
- Добавить редактируемый input `authority` в группу паспортных данных общей формы и применять к нему существующие правила неперезаписывающего объединения и сброса пользователя.
- Передавать текущее значение `authority` в DOCX как плейсхолдер `{authority}` и документировать новый реквизит.
- Расширить модели, IPC-валидацию и автоматические тесты новым полем без изменения поведения существующих паспортных полей.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `passport-file-recognition`: результат паспортного OCR дополнительно содержит орган выдачи `authority`, извлечённый из визуального поля паспорта.
- `document-data-workspace`: общая форма показывает, сохраняет, сбрасывает и передаёт в DOCX новое паспортное поле `authority` по действующим правилам работы с данными пользователя.

## Impact

- Python OCR: `ocr/mrz_parser.py`, паспортная модель и parser-тесты визуального поля `Authority`.
- Electron/renderer API: синхронные копии `PassportData` и `PersonalFormData`, allow-list результата OCR и валидация payload генерации.
- Angular UI: новый form control и компактный input в группе `Documents`, а также обновление компонентных тестов количества и слияния полей.
- DOCX и документация: поддержка `{authority}` в генераторе, тестовом шаблоне и `README.md`.
- Новые зависимости и breaking changes отсутствуют.
