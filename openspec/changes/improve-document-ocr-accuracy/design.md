# Design

## Context

OCR запускается локально на CPU отдельным Python-процессом. Тип документа известен до запуска, поэтому можно выбрать подходящую recognition-модель без повторного анализа результата. Парсеры уже проверяют контрольные цифры MRZ и форматы поддерживаемых полей.

Ранее реализованный резервный этап добавил confidence-оценки, растеризацию страниц, вырезание областей, коррекцию ориентации и перспективы, объединение кандидатов и отдельный benchmark. Реальные пользовательские примеры показали, что семантические ошибки символов всё равно возможны, а приоритетом стала простота кода.

## Goals / Non-Goals

**Goals:**

- получить основной эффект от более сильного детектора и специализированных языковых моделей;
- оставить один предсказуемый OCR-проход;
- сократить число моделей, объём кода и время запуска;
- сохранить внешний формат результата и существующую строгую проверку структурированных значений;
- сохранить автономную работу без сети.

**Non-Goals:**

- повторное распознавание отдельных областей;
- использование confidence для выбора между кандидатами;
- автоматическая коррекция перспективы и ориентации;
- словарное исправление географических названий и органов выдачи;
- встроенный benchmark на пользовательских документах;
- добавление новых полей или элементов интерфейса.

## Decisions

### 1. Один профиль на тип документа

Общий детектор — `PP-OCRv6_small_det`. Для паспорта используется `cyrillic_PP-OCRv5_mobile_rec`, для UAE Residence Permit — `en_PP-OCRv5_mobile_rec`. Константы хранятся в одном Python-модуле и используются runtime и сборщиком.

### 2. Один проход без preprocessing-моделей

Файл передаётся непосредственно PaddleOCR так же, как до изменения. Результаты страниц последовательно передаются существующим парсерам. Модели ориентации документа, исправления перспективы и ориентации строк не включаются.

### 3. Сохранить структурную валидацию парсеров

Контрольные цифры MRZ, форматы дат и идентификаторов остаются источником решения о допустимости структурированных значений. Общие текстовые поля могут содержать редкие OCR-ошибки и остаются доступными для ручной проверки пользователем.

### 4. Компактные тесты вместо benchmark-инфраструктуры

Unit-тесты проверяют точные имена моделей, параметры PaddleOCR, маршрутизацию по типу документа и существующие парсеры. Тесты не поставляются с приложением. Отдельные benchmark-скрипт, manifest и каталог данных удаляются.

## Risks / Trade-offs

- Поворот или сильная перспектива могут распознаваться хуже без резервного этапа. Это принято ради простоты; пользователь может переснять документ ровнее.
- Ошибки похожих символов могут сохраняться. Автоматические словарные исправления не добавляются без подтверждённого набора правил.
- Улучшенный детектор немного больше исходного `tiny`, но итоговая поставка меньше варианта с preprocessing-моделями.

## Rollback

Для отката достаточно вернуть `PP-OCRv6_tiny_det` и общую кириллическую recognition-модель; внешний API при этом не меняется.
