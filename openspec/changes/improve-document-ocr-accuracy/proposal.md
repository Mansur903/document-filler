# Proposal

## Why

Текущий локальный OCR использует сверхлёгкий детектор и одну кириллическую модель для документов с разными языками. Наибольший ожидаемый прирост при минимальной сложности даёт замена детектора и выбор модели распознавания по типу документа. Дополнительные проходы, confidence-объединение и коррекция перспективы усложняют код и увеличивают поставку, а их эффект на реальных документах не подтверждён.

## What Changes

- Заменить `PP-OCRv6_tiny_det` на `PP-OCRv6_small_det` для обоих типов документов.
- Использовать `cyrillic_PP-OCRv5_mobile_rec` для российского паспорта и `en_PP-OCRv5_mobile_rec` для UAE Residence Permit.
- Выполнять один OCR-проход без отдельных моделей ориентации, перспективы и повторного распознавания областей.
- Сохранить существующие проверки MRZ, дат и идентификаторов, а также прежний внешний контракт данных.
- Упаковывать только три необходимые OCR-модели и сохранить полностью локальную работу.
- Оставить компактный набор регрессионных тестов конфигурации моделей и извлечения полей.
- Удалить отдельный benchmark, confidence-объединение и связанные с ними тесты и документацию.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `passport-file-recognition`: локальное распознавание использует улучшенный детектор и кириллическую модель за один проход.
- `uae-residence-permit-recognition`: локальное распознавание использует улучшенный детектор и английскую модель за один проход.

## Impact

- Python OCR: упрощение `ocr/recognize_passport.py` и конфигурации моделей.
- Автономная сборка: `ocr/build_ocr.py` упаковывает только основной детектор и две языковые модели.
- Тесты: сохраняются только проверки основного маршрута, парсеров и выбора моделей.
- Angular/Electron API, DOCX-контракты и пользовательский интерфейс не меняются.
