# Proposal

## Why

Повторный выбор документа или DOCX-шаблона каждый раз начинается без учёта предыдущей папки. Кроме того, фиксированный набор полей формы не позволяет подставить в шаблон произвольные данные без изменения кода.

## What Changes

- Запоминать последнюю папку успешно выбранного входного документа и последнюю папку успешно выбранного DOCX-шаблона независимо друг от друга; использовать их при следующем открытии соответствующего системного диалога, в том числе после перезапуска приложения.
- Добавить создание строкового пользовательского поля через модальное окно с обязательной подписью `label` и именем плейсхолдера `name`, которое используется в DOCX как `{name}`.
- Показывать пользовательские поля в отдельном блоке общей формы, позволять вводить значения и удалять созданные поля.
- Сохранять определения пользовательских полей между запусками приложения. Введённые значения относятся только к текущему пользователю и после перезапуска не восстанавливаются.
- Передавать текущие значения пользовательских полей в генератор DOCX вместе с существующими полями, не допуская совпадения имён плейсхолдеров.

## Capabilities

### New Capabilities

- `file-dialog-directory-preferences`: отдельные сохраняемые последние папки для выбора входного документа и DOCX-шаблона.

### Modified Capabilities

- `document-data-workspace`: создание, отображение, удаление и сохранение определений пользовательских полей, очистка их значений для нового пользователя и подстановка в DOCX.

## Impact

- Electron main: параметры системных диалогов, локальное хранение настроек приложения, проверки и IPC для пользовательских полей.
- Angular: отдельный блок полей, модальное окно создания, динамическое состояние формы и работа с новым пользователем.
- Preload и общие модели: типизированный контракт загрузки/изменения определений и передачи текущих значений в DOCX.
- Генератор DOCX, тесты и README: динамические плейсхолдеры и правила их именования.
