# Document Data Workspace Specification

## Purpose

Определяет единую форму данных пользователя, которая накапливает результаты нескольких распознаваний, допускает ручное редактирование и передаёт совокупные значения в DOCX без неявной потери уже заполненных полей.

## Requirements

### Requirement: Единая панель данных пользователя

Система SHALL постоянно показывать в правой панели все поля российского заграничного паспорта, UAE Residence Permit и ручные поля `email`, `address`, `phone` независимо от того, какие документы уже распознаны. Панель SHALL использовать компактное расположение полей и собственную вертикальную прокрутку при нехватке высоты, не скрывая доступ к выбору и распознаванию документа.

#### Scenario: Форма открыта до первого распознавания

- **WHEN** пользователь открывает приложение для нового пользователя
- **THEN** правая панель показывает все поддерживаемые поля пустыми, включая `email`, `address` и `phone`

#### Scenario: Поля не помещаются по высоте

- **WHEN** высота окна недостаточна для одновременного отображения всех полей
- **THEN** пользователь может прокрутить правую панель и получить доступ к каждому полю без прокрутки или исчезновения панели выбора документа

#### Scenario: Значение отредактировано вручную

- **WHEN** пользователь изменяет любое поле общей формы
- **THEN** отредактированное значение немедленно становится текущим значением для дальнейшего слияния и генерации документа

### Requirement: Неперезаписывающее объединение результатов OCR

После успешного распознавания система SHALL заполнять только поля, текущее значение которых является пустой строкой, значением OCR, которое само не является пустым. Система MUST сохранять любое уже непустое значение независимо от того, получено оно предыдущим OCR или введено вручную, и MUST поддерживать распознавание паспорта и UAE Residence Permit в любом порядке.

#### Scenario: Сначала распознан паспорт

- **WHEN** пользователь сначала распознаёт паспорт, а затем UAE Residence Permit
- **THEN** поля разрешения заполняются без очистки паспортных и ручных полей

#### Scenario: Сначала распознан UAE Residence Permit

- **WHEN** пользователь сначала распознаёт UAE Residence Permit, а затем паспорт
- **THEN** паспортные поля заполняются без очистки полей разрешения и ручных полей

#### Scenario: Новое значение пересекается с заполненным

- **WHEN** новое распознавание возвращает непустое значение для любого уже непустого общего поля
- **THEN** система сохраняет текущее значение поля и игнорирует новое значение OCR для этого поля

#### Scenario: Новое значение заполняет пустое поле

- **WHEN** новое распознавание возвращает непустое значение для пустого поля
- **THEN** система записывает распознанное значение в это поле

#### Scenario: OCR вернул пустое значение

- **WHEN** новое распознавание возвращает пустое значение для любого поля
- **THEN** текущее значение этого поля не изменяется

#### Scenario: Пользователь вручную очистил поле

- **WHEN** пользователь удалил значение поля и последующее распознавание вернуло для него непустое значение
- **THEN** система считает поле пустым и заполняет его новым распознанным значением

#### Scenario: Выбран или заменён файл

- **WHEN** пользователь выбирает другой файл или отменяет диалог выбора
- **THEN** значения общей формы остаются без изменений

### Requirement: Ручные контактные поля

Система SHALL предоставлять редактируемые строковые поля `email`, `address` и `phone`, SHALL оставлять их пустыми после создания нового пользователя и MUST NOT заполнять их результатами OCR.

#### Scenario: Документ успешно распознан

- **WHEN** завершается распознавание любого поддерживаемого документа
- **THEN** текущие значения `email`, `address` и `phone` остаются без изменений

#### Scenario: Пользователь вводит контактные данные

- **WHEN** пользователь вручную вводит email, адрес или телефон
- **THEN** система сохраняет введённые строки в общей форме для текущего пользователя

### Requirement: Явное начало работы с новым пользователем

Система SHALL предоставлять отдельное действие `Новый пользователь`, которое очищает все поля общей формы, текущий входной документ, состояние распознавания и результат предыдущей генерации, но сохраняет выбранный DOCX-шаблон. Если в форме есть непустые значения, система SHALL запросить подтверждение перед необратимой очисткой.

#### Scenario: Сброс заполненной формы подтверждён

- **WHEN** пользователь запускает действие `Новый пользователь` при наличии данных и подтверждает очистку
- **THEN** система очищает все поля и состояние текущего пользователя, сохраняя выбранный DOCX-шаблон

#### Scenario: Сброс заполненной формы отменён

- **WHEN** пользователь запускает действие `Новый пользователь` при наличии данных и отменяет подтверждение
- **THEN** форма, выбранный входной документ и результаты остаются без изменений

#### Scenario: Сброс пустой формы

- **WHEN** пользователь запускает действие `Новый пользователь` при полностью пустой форме
- **THEN** система приводит рабочую область к начальному состоянию без обязательного подтверждения

### Requirement: Генерация DOCX из общей формы

Система SHALL передавать в выбранный DOCX-шаблон все существующие паспортные поля и поля `residencepermitID`, `visaID`, `visaValidUntil`, `currentOccupation`, `employer`, `email`, `address`, `phone`, используя текущие отредактированные значения общей формы. Для паспортной даты `validUntil` и даты разрешения `visaValidUntil` SHALL применяться существующее форматирование даты DOCX.

#### Scenario: Шаблон содержит новые плейсхолдеры

- **WHEN** пользователь генерирует документ из шаблона с новыми плейсхолдерами
- **THEN** каждый плейсхолдер заменяется текущим значением одноимённого поля общей формы

#### Scenario: Поле осталось пустым

- **WHEN** плейсхолдер присутствует в шаблоне, но соответствующее поле общей формы пусто
- **THEN** генератор обрабатывает его по единому действующему правилу для пустых значений и не использует данные из предыдущего пользователя
